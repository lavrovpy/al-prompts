# Area charter library

Starting points for `areas[].charter`. Adapt each to the app: name its real routes, components and files, and say which users and data partition the area may use. One area = one explorer (+ one verifier). Areas that only read data can run in parallel freely; areas that mutate data need their own user or id partition.

Proven yield on the first run (Opus explorers): confirmed findings per area ranged 3 (security) to 25 (accessibility); median ~13.

| key | Charter seed | Mutates? |
|---|---|---|
| `browse` | Home/list page: filters and their counts per persona (do private items leak into counts?), search (special characters `% _ ' " \ < >`, unicode, max length, empty, case), state in URL across reload/back/forward, ordering, pagination limits, loading and empty states, broken-media fallback, prefetch, header nav, light/dark theme (white-on-white), keyboard shortcuts actually working, 404, tab titles. Compare anon vs owner vs second user. | no |
| `viewer` | Detail view (modal and full page): open/close paths (X, Esc, backdrop, back), next/previous order and edges, deep links + hard refresh, scroll restoration, every inline-editable field (empty, whitespace, max length, emoji, HTML, non-Latin; Esc/blur/Enter), toggles, delete (confirmation, where you land, deleted id by URL), download (name, extension), what non-owners and anon see and can do; malformed ids. | own partition |
| `ai` | AI-powered actions through the UI: loading states and timing, double triggers, navigating away mid-request, persistence after reload and in search, limits (tags count, text length), unsupported inputs and the error text users see (raw provider errors?), output quality on known fixtures (exact text, language, invented content), non-owner access, retries, repeated paid calls. Read the action/hook/service code for edge cases. Note the model in environment_notes. | own user |
| `upload` | Upload paths (button, drag-drop, paste): accepted/rejected types and messages, size and count limits, quotas (find a way to see the quota message without burning quota), progress panel (multiple files, errors, cancel, retry), new item appears without refresh, name/visibility defaults, EXIF orientation, animated GIFs, odd file names; users without permission; anon. | own user, budget |
| `collections` | Albums/folders/projects: create (validation), nesting, tree view, breadcrumbs, rename, delete with children/items, move (drag-drop, into own descendant, to root), add/remove/move items, reorder, cover/auto-cover repair, counts after changes, empty states, other users' collection URLs. Read the query/action code for path/sort-order edge cases. | own partition |
| `bulk` | Selection mode and bulk toolbar: click/shift/ctrl selection, select all, keyboard shortcuts, count accuracy, selection across filters/search/navigation, every bulk action (delete, visibility, tags, add to collection, export ZIP — unzip and inspect), mixing own and others' items, grid state after the action. | own partition, delete cap |
| `security` | Enumerate every server action/route from the code, then attack from the running app as a second user and anon: replay actions with foreign ids (capture a real call via `network request`), private/NSFW data through every path (direct URL, search, counts, collections, export, prefetch, metadata, RSC/flight payloads), self-granting permissions, stored XSS in every user-controlled string, search abuse, unbounded paid calls, permission/quota bypass on upload endpoints, headers/cookies, secrets reaching the browser. Only report what you demonstrate. Expect refusal-fallback to an older model on some turns. | write *attempts* on a victim partition |
| `settings` | Settings page: what it shows, every toggle's end-to-end effect, persistence (reload, sign-out/in, other tab), failure handling (`network route --abort`), rapid toggling, user menu, sign-out redirect, anon and no-permission views. Restore the user's settings at the end. | its own user only |
| `mobile-browse` | Phones (iPhone 14, iPhone SE, Pixel 7, one landscape): header/tap targets, search field, filters, grid, cards, long names, detail view on a phone (panel, scroll lock, close reachability, keyboard covering inputs), touch tooltips, horizontal overflow (`scrollWidth > innerWidth` on every page), fixed elements covering content, first-screen load. | no |
| `mobile-manage` | Managing on phones: long-press selection, bulk toolbar and dialogs on 375 px, collections management without drag-drop, upload on a phone, settings, dialogs with the on-screen keyboard (shrink viewport height), toasts covering controls. | own user |
| `perf` | Measure on a production build: JS per route and largest chunks, image bytes vs rendered size, requests on load/scroll, LCP/CLS/long tasks (desktop + phone), TTFB per route (5 repeats), HTML/RSC payload waste, DB queries per page and per action (N+1) from the query log, hover-prefetch storms, requests per keystroke, DOM size, caching headers, backend latency under 5–10 concurrent requests. Report quantified problems. | no |
| `api` | Backend with curl against its contract: status codes, response and error shapes vs spec, input validation (missing/duplicate fields, bad URLs, unsupported/0-byte/oversized files, huge dimensions, bad query params), auth (missing/wrong key, public endpoints and what they disclose), methods/CORS, rate limits, concurrency/timeouts, temp-file cleanup after errors, error-message leakage. Evidence is .txt curl logs. | no |
| `a11y` | Keyboard-only and screen-reader view in both themes, at 1440x900 and 200% zoom: tab order, visible focus, focus trap and return in dialogs, Esc, accessible names of icon buttons (read them via `snapshot`), alt text, headings/landmarks, labels and errors, contrast ratios (compute from computed styles), aria-live toasts, reduced motion, lang, wording consistency, misleading copy. Cite WCAG criteria. | no |
| `state` | Cross-cutting state: fresh data everywhere after each mutation (lists, counts, search, detail, back), two tabs acting on stale data, double submits, network failures mid-action (`network route --abort`, `set offline on`) and rollback, slow responses, session ending mid-action, navigation while pending, bfcache, error boundaries and recovery, toast accuracy ("Successfully…" when nothing happened). | own user |
| `provider` | A third-party provider path on production configuration (payments, LLM, email, storage): real behaviour of the provider-backed endpoints, output quality on known fixtures, latency vs platform timeouts, prompt injection through user content, failure modes with a deliberately broken key/model on a second instance (status codes, leaked provider messages, fallbacks), cost per action and repeated paid calls. Set a hard call budget. | budget |
